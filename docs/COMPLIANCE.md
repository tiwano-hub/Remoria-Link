# 法令対応設計メモ（Remoria Link）

本システムは日本国内の以下の法令への準拠を意図して設計しています。本書は実装上の
方針をまとめたもので、最終的な法的判断は必ず専門家・所轄警察署・税理士に確認してください。

## 1. 古物営業法

### 1.1 取引記録（古物台帳）

古物営業法第16条・施行規則第17条に基づき、買受け（1万円以上等の対象取引）について
以下を記録します。本システムでは `Case` / `PurchaseItem` / `IdentityVerification` を
組み合わせて古物台帳に相当する記録を生成します。

- 取引年月日（契約日）
- 古物の品目・数量・特徴
- 買取金額
- 相手方の住所・氏名・職業・年齢
- 相手方の確認方法（本人確認）

**保存期間：最終記載日から3年間**（施行規則第18条）。本システムは安全側で
長期保存（実務上7年以上）を許容する設計とし、論理削除のみを行います。

### 1.2 本人確認（対面・非対面）

`IdentityVerification.method` で確認方法を区別します。

- **対面取引（出張・店頭）**：相手方の身分証の提示を受け、現物確認を行う。
  確認担当者・確認日時・身分証種別・身分証画像を保存。
- **非対面取引（宅配等）**：単なる身分証画像のアップロードのみでは不可。
  施行規則第15条に定める以下のいずれかの方法を選択・記録します。
  - 本人限定受取郵便等の利用
  - 身分証の画像送信＋有効性確認＋転送不要書留の送付
  - IC チップ情報の送信
  - 電子署名・公的個人認証 等

UI 上、買取方法（出張／宅配／店頭）に応じて選択可能な確認方法を制限し、
「身分証画像アップロードのみ」では非対面取引を完了できないようにします。

## 2. 電子帳簿保存法

電子取引・電子書類（契約書・領収書）について、真実性・可視性の確保を行います。

- **訂正・削除の防止／履歴の保存**：領収書・契約書は発行後に編集不可。訂正は
  「取消＋再発行」とし、`Receipt.status` と関連レコードで履歴を保持します。
- **検索機能の確保**：取引年月日・金額・取引先で検索可能（領収書一覧・販売実績）。
- **タイムスタンプ／改ざん検知**：発行時に `issuedAt` とコンテンツハッシュを保存。
- **保存期間：原則7年間**（欠損金がある場合等は最長10年）。

## 3. 個人情報保護法

- 顧客情報（氏名・連絡先・住所・身分証画像）は利用目的の範囲内で取得・保管。
- アクセス制御（RBAC）と操作ログにより、誰がいつ何にアクセス・変更したかを記録。
- 顧客に提示する画面・契約書・メール・SMS には社内情報を一切含めません
  （見込金額・販路・原価・粗利・社内メモ・社内専用写真・失点明細・担当者評価）。
- 身分証画像等のセンシティブ情報はアクセス権限を限定し、保存期間経過後に削除可能。

## 4. インボイス制度（適格請求書等保存方式）

- 領収書には発行者の登録番号（適格請求書発行事業者番号）を表示。
- 税込・税抜・消費税額を区分表示。税率はマスタ管理（初期 10%）。

## 5. 保存期間まとめ

| 区分 | 種別 | 保存期間（システム方針） |
| --- | --- | --- |
| 古物営業法 | 古物台帳・取引記録 | 3年（実務上7年以上を許容） |
| 古物営業法 | 本人確認記録・身分証画像 | 取引記録に準じ保存 |
| 電子帳簿保存法 | 契約書・領収書 | 7年（最長10年） |
| 内部統制 | 操作ログ | 7年以上 |

保存期間を経過したセンシティブデータは、管理者操作により安全に削除できる設計とし、
削除操作自体も操作ログに残します。
